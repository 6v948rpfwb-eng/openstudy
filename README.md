# 开卷

一个**学科无关**的练习引擎。学科是数据，引擎是代码。

> 目标不是"背单词式刷题"，而是让每一次练习都产生可用的信息：
> 你现在到底会到什么程度、哪一块真的不会、下一次该练什么。

---

## 它解决什么问题

大多数刷题工具的通病是**难度不匹配**：

- 全考简单题 → 谁都能考 90 分，练了一晚上什么也没测出来
- 全考难题 → 谁都考 20 分，除了打击信心什么也没得到

开卷的做法是让**难度摊开**：以你当前的能力为中心，把题目的难度铺成一条分布，太容易和太难的题自动降权。这个结论不是拍脑袋，是评测理论里的标准结果——**测评的信息量来自难度分布的分散度**，难度全挤在一起时，分数就不携带信息。

---

## 四个核心机制

### 1. 能力与难度共用一个刻度

能力 θ 和难度 b 都在 `[0, 1]` 上，预测通过率用 one-parameter logistic：

```
p = 1 / (1 + exp(-a * (θ - b)))        a = 4
```

于是：

| 情形 | 预测通过率 |
|---|---|
| θ = b（能力等于难度） | 0.500 |
| θ 比 b 高 0.25 | 0.731 |
| θ 比 b 低 0.25 | 0.269 |

答完一题就更新 θ：答对往上走 `lr * (1-p)`，答错往下走 `lr * p`。
**本来就该做对的题，答对了几乎不动 θ**——因为它没有提供新信息。

### 2. 组卷 = 按难度分层抽样

```
候选池 → 围绕 θ 收窄到难度带 → 按难度排序 → 切成 n 段
       → 每段按权重抽一题 → 同考点不超过 n/3
```

这样出来的卷子天然难度均匀。到期的复习考点会被加权，优先抽到。

**同考点复习时优先抽没做过的新题**——因为只有新题提供完整的能力证据（见下一节）。

### 3. 区分「真会」和「记住了这题答案」

间隔复习会把同一道题再出一次。这时答对有两种可能：

- 真的会了
- 只是记住了这道题的答案

外部看不出来。所以系统给每次作答算一个**证据权重**：

| 情况 | 权重 | 理由 |
|---|---|---|
| 第一次做这题，答对 | `1` | 完整证据 |
| 第二次做，答对 | `0.5` | 可能是记住了 |
| 第三次做，答对 | `0.333` | `1/(1+做过次数)` |
| 任何时候**答错** | `1` | 重复题还错，说明确实没学会，不打折 |

权重直接乘在 θ 的更新步长上。实测（`node tests/run.js` 第 7 节，同一道题连做三遍全对）：

```
第1遍（新题）  θ 0.35 → 0.382  涨 0.032  证据权重 1.000
第2遍（重复）  θ 0.382 → 0.397  涨 0.015  证据权重 0.500
第3遍（重复）  θ 0.397 → 0.406  涨 0.009  证据权重 0.333
```

增幅一路递减：**靠重复刷同一道题，是刷不出能力的**。

想要完整的证据，只能换一道没做过的新题。所以组卷时对做过的题降权
（`freshFactor = 0.3 + 0.7/(1+做过次数)`：新题 1.0，做过一次 0.65，两次 0.53）。

界面上一道题会标「新题」或「复习 · 做过 N 次」，做完后成绩页单独列出
「新题正确率」和「重复题正确率」，避免把两者混成一个数。

这个设计参照了 OpenMAIC 的
[最近发展区习题课](https://github.com/THU-MAIC/OpenMAIC/tree/main/skills/agent-runtime/zone-of-proximal-development)：
独立尝试、受助练习、新任务复核三段的表现必须分开记录。

### 4. 只判能被程序判的东西

| 题型 | 判分方式 | 可靠性 |
|---|---|---|
| `numeric` | 数值比较，相对容差 1% | 完全自动 |
| `choice` | 下标比较 | 完全自动 |
| `text` | **不自动判**，给参考答案让人自评 | 主观题无法可靠自动判 |

第三行是刻意的。硬判主观题会把错误写进能力估计，比不判更糟。
主观题的自评只写进记录，`countsForTheta: false`，**不参与 θ 更新**。

## 快速开始

### 方式一：单文件网页（最省事）

```bash
node build.js          # 生成 dist/openstudy.html
open dist/openstudy.html
```

双击 `dist/openstudy.html` 就能用，不需要服务器、不需要 `npm install`、不需要联网。进度存在浏览器 localStorage 里。

### 方式二：开发模式

```bash
python3 -m http.server 8000
# 打开 http://127.0.0.1:8000/web/
```

### 方式三：命令行自检

```bash
node tests/run.js      # 组卷 → 模拟作答 → 结算 → 排程，全流程跑一遍
node tests/smoke.js    # 用最小 DOM 桩验证网页脚本能跑到底
```

## 题库格式

一个学科一个 JSON 文件。核心只有一句：**每道题必须写出处**。

```json
{
  "subject": "physics",
  "title": "高中物理",
  "topics": {
    "P-01": { "name": "匀变速直线运动" }
  },
  "questions": [
    {
      "id": "q001",
      "topic": "P-01",
      "type": "numeric",
      "difficulty": 0.45,
      "stem": "一物体从静止开始以 2 m/s² 加速，4 s 后速度多大？",
      "answer": { "value": 8, "relTol": 0.01 },
      "solution": "v = at = 2 × 4 = 8 m/s",
      "source": "2024年浙江卷第12题"
    }
  ]
}
```

- `difficulty` ∈ `[0,1]`，0 最容易，1 最难
- `type` ∈ `numeric` / `choice` / `text`
- `source` **必填**：没有出处的题会被校验器拒绝加载

详见 [docs/格式说明.md](docs/格式说明.md)。

## 从真题 Markdown 导入题库

手写题库不现实。实际做法是：把试卷原文存成 Markdown，让导入器去解析。

```bash
node tools/import-md.js \
  --topics tools/topics-physics.json \
  --out openstudy-data/physics.bank.json \
  ../资料/2026-1月-浙江选考-物理-真题.md \
  ../资料/2026-6月-浙江选考-物理-真题.md
```

导入器认的原文格式（只要大致长这样就够）：

```markdown
**1.** 题干……（　　）
A. 选项一　B. 选项二　C. 选项三　D. 选项四

**15.（8 分）** 题干……
（1）第一问；
（2）第二问。

## 参考答案与解析

**1.【答案】C**
解析文字……

**15.【答案】（1）……　（2）……**
解析文字……
```

它会做这些判断：

| 原文长什么样 | 判成什么题型 |
| --- | --- |
| 有 A–D 选项、答案是字母 | `choice`，字母转成 0 起下标 |
| 没有选项、答案就是一个数 | `numeric`，带 1% 相对误差 |
| 有（1）（2）（3）多个小问 | `text`，参考答案取自【答案】，解析取自下文 |
| 选项是纯图（`A.　B.　C.　D.` 文字为空） | `text`，因为文字界面里没法点图 |

同时自动填上：

- `source`：`2026年1月浙江省物理选考 第1题`（校验器强制要求这个字段）
- `difficulty`：按题号粗排（1–10 最简单 → 18 最难），之后用你的真实正确率校准
- `needsFigure`：题干里有 `[图 …]` 就标上，界面会提示「这题原文带图」
- `topic`：按 `tools/topics-physics.json` 里的关键词归考点，没命中的进 `P-99 未分类`

**归错考点不用改代码**，改 `tools/topics-physics.json` 的关键词重跑就行。

跑完会打印一份核对清单：哪几道题没归到考点、哪几道原文没答案、哪几道的答案区对不上题干。

### 生成带真题的单文件网页

## 关于题库与版权

**本仓库不附带任何真题题库。** `data/example.bank.json` 只是格式示例，题面明确标了「示例」，不是真题。

原因有两条：

1. 历年高考试题的著作权归属各地教育考试机构，直接打包分发有法律风险；
2. 来路不明的题会污染能力估计——一道错题能让引擎得出完全错误的结论。

所以设计上是**题库与引擎分离**：你把自己的题库放进 `openstudy-data/`，引擎就能用。校验器强制要求 `source` 字段，就是逼着每道题都能追溯到出处。
